Shah Rukh Khan Voice Clone

Concatenative Voice Synthesis System

Complete 306 Words 48kHz Quality

A voice cloning system that uses ONLY Shah Rukh Khan's actual voice to create new sentences through concatenative synthesis.

Key Features

  • Speaker Identification: Automatically identifies and extracts only SRK's voice from videos
  • Filters out: Interviewers, announcers, and other speakers
  • Pure SRK Voice: Every word in the library is confirmed to be from Shah Rukh Khan

Quick Start

# Create a sentence
python3 srk_voice_clone.py "i think it is"

# Interactive mode
python3 srk_voice_clone.py

Available Sentences

The system can create sentences like:

  • "I think"
  • "I believe"
  • "My family"
  • "My films"
  • "You know"
  • "I think it is"
  • And many more...

How It Works

  1. Speaker Identification: Analyzes transcripts to identify when SRK is speaking
  2. Voice Extraction: Extracts only segments where SRK is speaking
  3. Word Library: Builds a library of individual words (306 unique words)
  4. Concatenative Synthesis: Combines words to create new sentences

Expanding the Library

To add more SRK words:

  1. Add YouTube video URLs to processing scripts
  2. Run speaker identification to separate SRK from others
  3. Extract only SRK segments
  4. Add to word library

Audio Quality

  • Accurate word boundary detection
  • Natural spacing between words

What I Learned

The headline lesson: concatenative synthesis trades flexibility for zero hallucination, and for a clone that's the right trade. Neural TTS can say anything but doesn't sound like SRK; this library sounds exactly like SRK but only says words he's actually said. The constraint was deliberate — for voice cloning, fidelity to the source beats generality. A clone that hallucinates a phrase SRK never said is a broken clone.

Second: speaker identification is the whole game. 306 words of pure SRK is usable; 306 words contaminated with one interviewer phrase is broken. The pipeline spends more compute filtering SRK from non-SRK (analyzing transcripts, isolating segments, verifying each word) than on the synthesis itself. The filtering is the product.

Third: multiple pronunciations per word is a feature, not a bug. 672 versions of 306 words means the library captures SRK saying "I" in a statement, in a question, and trailing off in a laugh. Picking the right version for context is what makes a sentence sound natural instead of stitched. A single canonical pronunciation per word would have been a robot voice, not a clone.

Fourth: audio hygiene is non-negotiable and entirely unglamorous. 48kHz sample rate, fade in/out to prevent clicks at word boundaries, accurate word boundary detection, natural inter-word spacing. None of this is interesting; all of it is the difference between a sentence that lands and one that sounds chopped. The 80/20 of audio quality lives in the edge cases between words, not in the words themselves.

Fifth: the vocabulary is the ceiling, and I chose that ceiling on purpose. Every new sentence has to be expressible in words SRK has already said. That's the cost of purity — the library size (306 words) is the hard limit on what can be said, and growing it requires finding clean new source audio, not just calling a model API. Honest about the trade: I picked fidelity over extensibility.
